# 系列设定：GitHub 项目推荐

> 系列级设定，**一次性定死，长期不改**。单期只填 `video/plans/<系列>-<期号>-<repo>.md`，
> 这里的东西不再重新讨论。要改这里，先问主人。

## 一、这是什么

一个日更的短推荐系列：**每期 30 秒，只讲一个 GitHub 项目，只讲一件事——它解决了谁的什么麻烦。**

不做评测、不做教程、不做「十大神器盘点」。观众看完应该只记住两样：**项目叫什么**、**它能干什么**。

## 二、受众

写代码的、想写代码的、以及被 AI 工具刷屏刷到麻木但还想知道「哪个是真能用」的人。
他们刷抖音，不看 B站专栏，耐心约等于 **3 秒**。

由此推出三条铁律：

1. **第一句话不许介绍项目**。先抛麻烦或反常识，项目名放到第 3 秒之后。
2. **不解释原理**。说「不用 root」，不说「基于 PRoot 的 user-space 容器」。
3. **每个卖点必须能被截图证明**。说不清长什么样的功能，不配进 30 秒。

## 三、硬规格

| 项 | 值 | 备注 |
|---|---|---|
| 时长 | **30 秒**（28~32 可接受） | 超 33 秒砍内容，不是砍语速 |
| 画幅 | **横屏 1920×1080**（默认，不许改） | 全系列统一横屏，竖屏不做 |
| 版式 | `review` 展示型（截图/录屏 + 字幕条 + 数据卡） | 见 `video/templates/review/` |
| 更新 | **日更**，每天 1 期 | 库存低于 3 期就停止消耗，先补策划 |
| 口播 | 约 **115~130 字** | 中文 TTS ≈ 4 字/秒，含停顿 |
| 分镜 | 固定 **5 个镜头** | 见下方时间轴 |
| 音乐 | 无 BGM 或极轻底噪 | 30 秒塞 BGM 只会糊住口播 |

## 四、固定时间轴（5 镜，不改）

| 镜 | 时间 | 任务 | 画面 |
|---|---|---|---|
| 1 | 0–3.5s | **钩子**：反常识 / 数字 / 结果前置 | 项目 hero 图或最能说明问题的那张截图，满屏 |
| 2 | 3.5–10s | **痛点具象**：让观众完成「这就是我」 | 纯排版划掉旧方案，或对比画面 |
| 3 | 10–18s | **主卖点**：只讲一个，讲透 | 功能截图或 3 秒录屏，局部放大 |
| 4 | 18–24s | **次卖点**：一个就够，别贪 | 第二张截图，可做分屏 |
| 5 | 24–30s | **落地**：去哪拿 + 一句坦白 | 仓库地址大字 + 缺点小字 |

镜头 3、4 之间**不许有转场特效**，硬切。30 秒里任何一秒花在特效上都是浪费。

### 前三秒的三个动作

一条片子能不能起量，前三秒决定 80%。这三秒要同时完成三件事，少一件就掉一个量级：

| 动作 | 靠什么 | 反例 |
|---|---|---|
| **停下来** | 反常识，或一个具体到不可能的数 | 「今天给大家推荐一个项目」（没人关心） |
| **看完** | 抛完数字立刻留一个没答的问题 | 把结论一次说完，观众没有理由往下看 |
| **想转** | 让观众想到「某个人需要这个」 | 只说「很强很好用」，谁都不需要 |

写法：**反常识在前，数字在后**。先给一句「安卓手机能跑 Ubuntu」让人愣一下，
再接「一周四千四百星」把可信度补上。反过来先说数字，观众会当成又一个软文标题划走。

「想转」不靠台词硬求，靠**结尾那半句坦白**（比如「只有安卓」）——
它制造了一个具体的遗憾，iPhone 用户会去评论区报到，安卓用户会转给同事。
被骂总比没人说话强。


## 五、选题门槛（不满足就不做）

- **必须有可演示的界面**。纯库、纯 CLI、纯框架一律不做——观众看不见东西。
- **首发 90 天内** 或 **近期有大版本更新**。日更系列靠新鲜度活着，炒冷饭没人看。
- **中文用户能用**。英文文档可以，但至少要能装得上、跑得起来。
- **不推荐**：需要企业资质才能用的、要付费才能看到效果的、作者明确拒绝社区的。

三条里满足两条即可；star 数不作为门槛（新项目 star 少正常，反而是信息差）。

## 六、标题规则

- 抖音 5 条候选、B站 3 条候选，**每期都要给满**，不许只给一条。
- 抖音标题：≤20 字，口语，可以不带项目名（用「这个项目」指代）。
- B站标题：≤30 字，带项目名 + 一句技术定位，方便搜索。
- 禁用词：「震惊」「逆天」「天花板」「神器」「必看」——这类词一出现，专业感归零。

## 七、封面规则（四要素 + 三层景深）

封面不是「视频的一帧」，是**一张独立的海报**。必须有四样东西，缺一不可：

| 要素 | 位置 | 做法 |
|---|---|---|
| **大肥鱼** | 前景 | 立绘贴纸质感，硬投影（0 模糊），不许虚 |
| **项目图片** | 中景 | 一张清晰的截图，带白边 + 硬投影，像贴在墙上的画 |
| **大字标记** | 中景 | ≤8 字，一排 ≤6 字，朱红或深蓝，白色描边 |
| **景深** | 全画面 | 三层焦平面，见下 |

三层焦平面是纵深的来源，不是靠加特效：

- **远景**：项目截图平铺成一面「墙」，`blur(28px)` + 压暗 55%，只读作「一堆界面」，
  不许让人看清任何一个字。
- **中景**：大字 + 那张清晰的截图，整体绕 Y 轴内旋 10~13°，近大远小。
- **前景**：大肥鱼，全清晰，硬投影压在画面左下。

**全清晰 = 全平淡。** 三层里必须有两层是虚的，主体才立得住。

文案还是两行、每行 ≤6 字：第一行名词，第二行结果。不许出现「推荐」「第 N 期」。

尺寸：**`1920×1080` 横屏**，和正片同一画幅。

> 🔴 **全系列默认横屏，不再出竖屏。** 2026-11-02 定：封面、正片、模板一律 1920×1080。
> 竖屏只在 diary / talk 那两个日记体模板里保留，项目推荐系列不用。
> 出片前先看一眼画幅，竖屏录出来等于白跑一遍 TTS。

## 八、封面到正片的转场（0.6 秒，不许硬切）

封面是静态图，正片是动态页。直接切过去会有一下「跳」，观众立刻察觉这是拼的。

做法是**解构**，四个动作同时发生，0.6 秒完成：

1. 中景那张清晰截图 **放大 + 从透视状态回正**，落到正片画框的位置
2. 大肥鱼 **向左滑出**画面
3. 远景的虚化墙 **淡出**成纯深色底
4. 大字标记 **缩小**，变成顶栏的期号

关键：**转场和第一句口播重叠**。配音从 0 秒就开始念钩子，画面在念的同时展开。
先让观众听到，再让画面跟上——声音先行的转场不会让人觉得「等了半秒」。

实现方式：在 `review` 模板里做 intro 场景（同一 DOM、同一套字体和颜色），
**不要用 ffmpeg 拼封面 + 正片**。拼接会有 1~2 帧色差和字体基线偏移，
在手机小屏上看不出来，但一旦有人截图对比就很明显。

> ✅ 已实现（2026-11-02）：`video/templates/review/index.html` 的 `#intro` 层 +
> `playIntro()`。封面数据由 `make.mjs` 从 `coverText`（`第一行|第二行`）拆出来传，
> 中景截图取**第一镜**的图，转场结束正好落进画框。
> 🔴 改模板时别删 `#intro`：删了不会报错，成片只是安静地少了整个片头。


## 九、每期必须交代的风险

推荐新项目不提坑，评论区第一句就是「你用了几天就敢推」。所以每期策划里
**必须写一条「这项目现在还不能干什么」**，并且尽量在口播里留半句给它。
真诚比吹捧更能涨粉。

## 十、产出物清单

一期完整产出 = 四个文件，缺一不可：

1. `video/plans/github-picks-<nn>-<repo>.md` —— 策划（人审，**审过才往下走**）
2. `video/scripts/_script_<repo>.json` —— 机器脚本（由策划派生，喂 `video/make.mjs`）
3. 成片 mp4
4. 封面 png（1920×1080 横屏）

策划未经确认，不许生成视频。
