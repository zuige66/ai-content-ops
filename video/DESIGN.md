# 大肥鱼视频设计规范（v1，2026-10-30）

> 从「大肥鱼日记」（dsh-bili-whale，745★）拆解 + `distinctive-ai-design` 的
> 「探索→定义→交付」方法论落地。模板不许自创样式，一律从这里取 token ——
> 模板感不是来自某个单独样式，而是来自缺乏意图和层级。

## 一、内容策略（比视觉值钱，先读这个）

学「大肥鱼日记」最该抄的不是 CSS，是它怎么**用真实运行日志讲故事**：

1. **系列化**：「大肥鱼日记 day0/day1/day2…」——每支是一个 Day，观众追更。
   模板顶栏的 Day 徽章就是为这个设计的。
2. **真事改编**：她真刷了 B站（「今天看了五条视频，只有一条让我笑了」）、
   真被评论轰炸（「我罢工了，评论不回了」）、真有 token 账本（「token 就是白饭」）。
   zhibo-auto 的日志/账本就是素材库，别编。
3. **悬念标题**：「两万人问我主人的钥匙是什么」——先抛数字和疑问。
4. **人设自洽**：所有梗从「一条住在电脑里的鱼」长出来（token=白饭、
   钥匙=主人的 API key），不要出戏玩别人的梗。
5. **克制**：日更≤1、发布时段随机化、AI 生成内容声明做进画面右上角（合规还加分）。

## 二、视觉 token（diary / talk 共用；review 见第五节）

| token | 值 | 用途 |
|---|---|---|
| `--bg` | `#E7F0F9` | 底色（极浅蓝） |
| `--dot` | `rgba(255,255,255,.75)` | 点阵纹理（纸感） |
| `--ink` | `#14304A` | 正文（深蓝黑，不用纯黑） |
| `--border` | `#1E3A5F` | 粗描边（3~5px，漫画/像素风） |
| `--accent` | `#F5991C` | 强调橙（徽章/光标/音波/Day N） |
| `--card` | `#FFFFFF` | 气泡/信息卡底 |
| `--shadow` | `4px 6px 0 rgba(30,58,95,.28)` | 硬偏移阴影（不模糊！） |
| 字体 | 微软雅黑 Bold | 数字/标题，别用细体 |

配色铁律：**白卡 + 深蓝描边 + 橙强调 + 浅蓝底**，四样之外的颜色一律不加。
渐变、发光、模糊阴影禁用（硬阴影才有手作感）。

## 三、构图（竖屏 1080×1920）

```
┌──────────────────────────────┐
│ 大肥鱼 的 {日记名}  [Day N]  [AI 生成内容] │ ← 顶栏：标题+橙徽章+灰声明
│                              │
│ ┌────────────┐               │
│ │[大肥鱼] 气泡正文 ▌│        │  │ ← 左：对话气泡（占 2/3 宽）
│ │            音波 ▪▪▪│      │  │    右：皮套立绘常驻（微微浮动）
│ └────────────┘            🐋  │
│ ┌─ 信息卡（偶发）─┐           │
│ │ 2 万 / 80 斤    │           │ ← 数字大字 + 小字注释
│ └───────────────┘           │
└──────────────────────────────┘
```

- 立绘：`--border` 无、保持 PNG 原样，`filter: drop-shadow` 轻托底，浮动 ±14px / 2.4s
- 气泡：出现时 `translateX(-40px)→0` + 淡入 0.45s；当前气泡音波动画，已过气泡静止
- 信息卡：气泡流中**偶发**（一支视频 1~2 张），仿系统窗口：小标题栏 + 大数字 + 小注释

## 四、动效与节奏

- 气泡切换：按 TTS 时长**按字数加权分配**，每段 ≤24 字，一段说完换下一段
- 动效时长：入场 0.45s（ease-out）、浮动 2.4s 循环、音波 0.9s 循环——没有别的动画
- 结尾不 outro（参考账号就是说完即止），留 0.8s 持住最后一句
- 时长：60~110s/支（参考区间 74~109s，太短没叙事、太长掉完播）

## 五、review 展示型（第二套视觉，只管项目推荐系列）

前四节是「角色说话」的语言：白卡、深蓝描边、橙强调、皮套立绘。
**review 不用这一套**，它是「物证陈列」——没有角色，只有截图和一句话。

硬套白卡蓝框的结果是：浅色的 GitHub 截图贴在白底上，边界糊成一片，
观众分不清哪是界面、哪是包装。所以它单独一套：

| token | 值 | 用途 |
|---|---|---|
| `--ground` | `#0E1116` | 底色（近黑，不是纯黑；纯黑在手机上死板） |
| `--frame` | `#12161C` | 画框内衬 |
| `--paper` | `#F5F1EA` | 说明牌（全屏唯一亮块） |
| `--red` | `#D2452F` | 朱红，唯一强调色 |
| `--dim` | `rgba(245,241,234,.5)` | 次要信息（仓库地址、AI 声明） |

三条铁律：

1. **一个亮块**。全屏只有说明牌是浅色。数据（4,389★）靠这个对比自动成为重心，
   不许再加箭头、圈、发光。
2. **画框占 46% 高**（960×880）。截图是主角，其余元素全部让位。
3. **一镜一个卖点**。镜与镜之间硬切，不做整屏转场——30 秒花 0.4 秒转场等于白扔一帧。
   **但「不做转场」只管镜间，不管片头和镜内**，见下。

### 动效分三层，别混成一层

这一套最容易做错的地方：把「不要转场」理解成「不要动」，结果全片只剩一个
图片放大。三层各管各的：

| 层 | 什么时候 | 做什么 | 为什么 |
|---|---|---|---|
| **片头** | 0 ~ 0.9s | 封面四要素 → 0.62s 解构转场 | 封面是独立海报，得先让人看清，再拆开接正片 |
| **镜间** | 每次切镜 | 硬切，只换内容 | 转场会吃掉信息时间，30 秒经不起 |
| **镜内** | 每镜全程 | 位移入场 / 划线生长 / 数字滚动 / 红条拉伸 / 慢推 | 镜头在动，观众才觉得画面是活的 |

**片头（intro）**：实现在 `review/index.html` 的 `#intro` 层，不是拼封面 png。
四个动作同时起跑，0.62s 完成：

1. 中景截图放大 + 从 `rotateY(-16°)` 回正 → 落进画框 `#win`
2. 大肥鱼左滑出画面（带 -9° 旋转）
3. 远景虚化墙 + 压暗层淡出成深色底
4. 大字缩小飞向左上角，读作「收进了顶栏期号」

转场必须**和第一句口播重叠**：配音 0 秒就念，画面 0.3s 才开始拆。
声音先到、画面跟上，观众不会觉得「等了半秒」。

**镜内五个动效**，一个都不能少，也别再加第六个：

- 截图从右侧 54px 位移入场（`#shotIn`），慢推在 `#shot` 上，两层分开
- 划线用 `::after` 的 width 生长，不用 `text-decoration`——原生删除线动不了
- 数据卡数字从 0 滚到目标值（`4.4k` 只滚数字，后缀钉住）
- 关键词红条 `scaleY(0→1)`，文字延后 0.13s 跟上
- 字幕上浮 14px + 淡入

🔴 **不要用两个 scale 叠同一个元素**。入场位移和慢推必须挂在不同层上，
否则两个 `transform: scale()` 互相覆盖，看起来像"没动"。

版面是「画框 + 说明牌」：上半装裱截图，下半贴说明牌（关键词 / 数据）。
说明牌里 `big` 有值才出数据卡，`key` 有值才出关键词行——**空着就不出现**，
不留空槽位。

### 大肥鱼常驻，位置跟着版式走

每一镜都有大肥鱼，越往后越小（205 → 175 → 170 → 165 → 170）。它是系列的签名，
不是主体，**超过 210px 就会盖住截图里的手机**。

位置不能一刀切，得看这一镜的正文在哪：

| 镜型 | 鱼放哪 | 原因 |
|---|---|---|
| 截图镜（镜 1/3/4） | 左下角 | 左下是截图边缘，压一点无妨 |
| 排版镜（镜 2/5） | **右下角** | 左栏从 x=88 起就是正文，鱼摆左下会直接压住「装 Termux」这种大词；右下便签下方是这块版面唯一的死区 |

实现：`#pet.petR` + `#typebox.petr`，由 `apply()` 按 `s.win` 切换。
`bottom` 必须是 `0` —— 素材（676×693）脚底正好压在下边界，给负值会被
`overflow:hidden` 横切一刀，鱼脚就没了。

### 镜 4：两端连线，换掉「大图 + 右牌」

镜 3 和镜 4 都是「手机 + 关键词」会看着像重复。镜 4 改用 `duo` 版式：
左说明牌 + 右两张卡（本机 / 电脑）+ 中间一条带脉冲的连线。

借的是 video-shotcraft 的 `integration-hub-map` 骨架。核心是那条**会流动的线**：
静止的线读作「两个东西并排」，有脉冲才读作「数据正在过去」。

🔴 `#duo` 用 `visibility:hidden` 不用 `display:none`，理由和 `#typebox` 那个坑一样。

### 主标题的重点词用马克笔底划

标题里写 `*写代码*`，渲染成 `<em>`，底下一条朱红横线从左画出来。
借 video-shotcraft 的 `marker-underline-title`，三个命门照抄：

- **快**：一笔 0.34s。慢了读作加载条
- **近**：贴字底 8px（≈0.1em）。离远了读作分隔线
- **跟字势**：`rotate(-.8deg)` 微上斜。纯水平线读作 CSS border，不是手画的

时机在标题落定之后起笔（delay 0.46s）——划线是「看完标题后的强调」，同动就抢戏。

### 排版镜（没有截图的镜）不许只放两行字

痛点镜和落地镜没有截图可用（「折腾 Termux」没有截图能证明，编一张假的更假），
走 `win` 文字层。**这一层最容易做塌**：早期版本是「屏幕正中两个词 + 底下一行字幕」，
1800×700 的画框里只有 250px 高的内容，上下各空 200px，看着像没做完。

现在固定成 **左文右卡 + 底栏** 三件套：

| 区 | 放什么 | 规矩 |
|---|---|---|
| 左栏 | 眉题 + 主标题 + 条目 | 主标题 96px、条目 80px，**字号本身就是内容**，靠加装饰补不回来 |
| 右栏 | 纸白便签（`card`） | 结论或代价，一句话说死；`min-height:300px` 别让它缩成小贴纸 |
| 底栏 | 3 格（`foot`） | 每格必须是观众真想知道的（术语释义 / 下载地址），**不许拿装饰横线凑数** |

内容不够撑满时，**先放大字号，再加真信息**，不要靠留白和装饰线。

动效四拍，顺序不能乱：眉题 → 标题 → 条目逐条上浮（间隔 0.08s）→ 便签压下来 → 底栏。
划线在条目落位后 0.23s 起长，两行间隔 0.15s。

🔴 **延时别拉太长**。第一版眉题 delay 0.05s、标题 0.12s，切镜后前 3~4 帧
画框是空的 —— 前一镜还是亮截图，一下切成纯暗，读作闪黑。
压到 0.02 / 0.07 之后空档只剩 1 帧，观众感知不到。

🔴 **两个坑，都不报错**：

1. **动画挂在 `.on` 上会整段失效**。`#typebox` 默认 `display:none`，
   加 `.on` 那一帧它才第一次被渲染，浏览器对「上一帧还不存在」的元素
   不启动过渡，属性直接跳到终值。所以 `.on` 只管显示，`.in` 在下一帧再挂。
2. **先挂类再写 `transitionDelay` 等于没写**。过渡已经按 `delay:0` 起跑了，
   之后再改延时只改一个已经用掉的值。必须：摆初始态 → 设延时 → 强制回流 → 再点亮。

两处都是「画面只是不动」，控制台一片安静，只有逐帧采样才看得出来。

### 镜 3：剖面（`core`），不要「一张图 + 一段话」

讲「手机里到底是什么」这种结构问题时，横屏截图缩到 286px 只剩 143px 高，
等于把信息全删了。改成**左实机 + 右剖面**：左边竖屏手机图（590×1210）撑满高度，
右边三层 `.lay` 依次滑入（应用 / 环境 / 内核），每层「层名 + 具体值」两行，
底下压一个 `.noroot` 徽标把结论钉死。三层必须**从下往上**讲（内核→容器→应用
反过来读，观众才理解「借用 Android 自己的内核」是什么意思），但**动画从上往下**
落位，读起来是「剥开」，不是「堆上去」。

**手机要真 3D**：`perspective:1500px` + `rotateY(-46deg) → rotateY(-13deg)`。
停在 0 就是一张平面截图，停在 -13° 才有「立体的东西被打开」的读法。
三层从 `translateX(76px) rotateY(18deg)` 抽出来，和旋转同一条时间线。

**引线（SVG）**：从手机右沿拉三条贝塞尔曲线接到每层。没有线，「手机」和
「三层」只是并排的两坨东西，关系得观众自己猜。三条线的 `d` 在 JS 里按布局算，
🔴 两种量法各有一个坑，混着用：
- `.cl` / `.cr` 没有 transform → 用 `getBoundingClientRect`；
- `.lay` 此刻挂着 `translateX(76px) rotateY(18deg)`，rect 量到的是**投影后**的
  盒子 → 只能用 `offsetTop/offsetLeft`（布局值）；
- 但 `.lay` 的 `offsetParent` 不是 `#core`，是 `.cr`（**`perspective` 会建立
  包含块**），所以要再加 `.cr` 的位置。直接用 `l.offsetLeft` 会把三条线
  全画到画框最左边（x=2），而且不报错。

### 镜 5：收尾做成发布会合影（Q8）

结尾不能是「一行字淡出」。三件套：**缩略图一排 + 地址解码 + 元信息标签**。
缩略图按 `height:200px;width:auto` 对齐 —— 竖屏手机和横屏 repo 截图的宽高比
差三倍，用 `width` 定宽会一排高低不齐。地址用 **text scramble**（乱码逐字
解锁成真地址，见下），解完停一下再上 meta 标签（协议 / 系统 / 限制）。
「只有安卓」这种真限制用 `hot` 标红，**不要藏短板** —— 观众信你才关注。

### 地址用解码（scramble），不用打字机

打字机是从 0 个字长到满，等宽地址会把右边的东西一路顶开；scramble 一开始
就占满整行，只有内容在变，**版面不跳**。逐字解锁按 `pow(p,1.6)` 前松后紧，
读作「越解越快」；线性读作「卡住了」。乱码字符集只留大写字母 + 数字 + `/._-`
—— 混进小写字母会让整行在解码中轻微抖动（等宽字体里高宽比不同）。

### 小字禁令（2026-11-02 用户明确要求）

> 「这是推荐项目的视频，就不要有小字，小字别人看视频会很难受。」

**1080 宽画面上，任何要读的字 ≥ 32px。** 这条优先于「信息密度」：
宁可删信息，不许缩字号。本轮实际删掉的东西：

| 删掉的 | 原字号 | 为什么 |
|---|---|---|
| 右上角「AI 生成」 | 18px | 纯标注，没人读，只让画面脏 |
| 眉题 `kicker`（「以前的办法」） | 22px | 和主标题说同一件事，重复 |
| 底栏 `foot` 三格 | 17px / 27px | 术语表。信息搬进条目说明（34px），底栏删掉 |
| 数据卡说明 `#card .s` | 18px | 放大到 32px，不删（它承载信息） |

放大的：条目说明 26→34、便签 26→32、剖面层 34→46、层名 23→32、编号 19→26、
徽标 24→32、duo 备注 24→32、标签 17→26、meta 25→34、顶栏系列名 25→34、
底栏仓库地址 22→30、数据卡数字 68→92。

**判断标准**：把这一行缩到手机宽度（约 1/3 屏幕）还能不能读？读不了就删或放大。
「信息不够」的解法是放大字号 + 加真信息，不是拿小字填空。

## 六、声音层（`video/audio.mjs`）

旁白之外必须有两层：**BGM（侧链让路）+ 钉帧 SFX**。

- **SFX 时刻从 `segStarts` 派生，不许写死秒数**。改一句旁白整条时间轴就漂了。
- **BGM 必须走侧链压缩**，不能靠手调音量：`sidechaincompress` 以人声为侧链，
  人声一响 BGM 自动掉 7~8dB，说完自己回来。手调只能取一个折中值，
  要么人声被盖，要么间奏太空。
- **`amix` 用 `duration=longest`**：人声比画面短时，`first` 会把片子截断。
- **`sidechaincompress` 输出长度跟侧链走** —— 侧链要 `apad=whole_dur` 补到片长，
  否则片子尾巴突然安静，而且**不报错**。
- **同一个带标签的 pad 只能消费一次**。人声既进 amix 又当侧链，必须
  `asplit=2`。报错是 `Invalid stream specifier: vox`，指向标签名，
  极易误判成拼写问题。
- 电平自查（`atrim=start=x:duration=d,volumedetect`，**不要用 `-ss`**）：
  转场 impact ≈ -11dB、划线 ≈ -9.6dB、收尾 impact ≈ -12.7dB 是合适的；
  低于 -30dB 等于没放（当前封面 whoosh -43dB 就偏轻，待调到 0.35）。

音效选型见 `video-shotcraft/references/aesthetic-rules.md` S1/S2/S4：
按片种选、连发双样本交替、拟音优先于电子音。

## 七、评审流程（借 distinctive-ai-design）

新模板/改模板必须：渲染真实 mp4 → 抽关键帧 → 对照参考图自查
（构图/层级/减法三问：每个元素帮观众理解了什么？）→ 最多两轮改，每轮只改 1~3 个最伤的问题。
截图评审不通过不许投稿。

预览捷径：`node tools/review-preview.mjs` 直接出 5 张关键帧，
不用跑完整的 TTS + 录屏。
